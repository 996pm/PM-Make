# 产品定型提问手册

## 轻量推进顺序

1. 先收敛一句话，不先问细节。
2. 再确认用户和场景，不先画功能清单。
3. 用 JTBD 找真实动机，再拆 MVP。
4. 最后落到页面、流程、规则、数据和权限。

## 问题库

### 产品定位

- 这个产品希望用户在什么场景下使用？
- 如果只能解决一个问题，最应该解决什么？
- 用户为什么不用现有方式继续解决？

### JTBD

- 当用户遇到什么情境时，会想找一个新方案？
- 用户想完成的实际进展是什么？
- 用户希望自己感觉更省心、更专业、更安全，还是更高效？
- 谁会评价这件事做得好不好？

### 四力分析

| 力量 | 要确认的问题 |
| --- | --- |
| Push | 现状中最让用户难受的触发点是什么？ |
| Pull | 新方案最吸引用户的收益是什么？ |
| Anxiety | 用户最担心什么失败、成本或风险？ |
| Habit | 用户为什么会继续沿用旧方式？ |

### MVP 边界

- 没有哪 3 个能力，产品就无法成立？
- 哪些能力只是增强体验，可以延后？
- 哪些能力容易被误以为要做，但本期明确不做？

### 流程与规则

- 用户从哪里进入，第一步做什么？
- 正常完成路径有哪些步骤？
- 哪些节点会失败、回退、取消、超时或需要审批？
- 哪些角色能看、能改、能审批、能导出？
- 哪些数据由用户填写，哪些来自系统或外部来源？

## 定型摘要写法

- 用确定句表达已确认内容。
- 用 `[待确认: ...]` 表达缺口。
- 不把参考案例、模板标题或可能性写成已确认范围。
- 冲突信息单独列出，不自行裁决。
